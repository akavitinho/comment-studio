## Instalar a partir do código

Requer Windows, Node.js e FFmpeg/FFprobe no `PATH`. Execute `npm ci` e `npm start`. Para gerar o instalador, mantenha o `yt-dlp.exe` em `vendor/` e execute `npm run dist:win`. Dados de contas, sessões e configurações ficam em `.local/` e não fazem parte do repositório. O arquivo `.env.example` lista as variáveis opcionais dos diagnósticos.

Para publicar Reels, crie seu próprio projeto Supabase, aplique as migrações de `supabase/migrations`, habilite **Anonymous Sign-Ins** e implante as Edge Functions `instagram-exchange` e `meta-callback`. Configure `INSTAGRAM_APP_ID` e `INSTAGRAM_APP_SECRET` como segredos das funções. No aplicativo, preencha **Postagens → Storage** com a URL do projeto e a chave **publishable**. Use `https://SEU-PROJETO.supabase.co/functions/v1/meta-callback` como URL de retorno no aplicativo e no produto Instagram do painel Meta. A URL e a chave publishable são configuração pública; segredos, tokens e sessões ficam fora do GitHub. Os testes de integração aceitam `STUDIO_SUPABASE_URL` e `STUDIO_SUPABASE_KEY` no ambiente.

Para métricas do TikTok, configure a Client Key e o Client Secret pelo próprio aplicativo. O segredo é salvo localmente com a proteção do Windows. A pasta `pressel-18/` é um site estático independente; veja o README dela antes de publicar.

O arquivo `docs/politica-de-privacidade.example.html` é um modelo. Preencha os dados do responsável antes de publicar sua própria política; a política local personalizada não é enviada ao repositório.

## Postagens Instagram — versão local não comercial

Em **Contas**, cadastre o perfil Instagram e selecione conexão direta ou proxy. Clique em **Conectar Instagram**, autorize com o perfil profissional desejado e confira o @ antes de vincular. Cada cadastro tem sua própria autorização e fila. Vínculos antigos via Facebook exigem reconexão.

O projeto Supabase usa o bucket privado `posting-videos`, criado pela migração em `supabase/migrations/20261104222904_private_posting_videos.sql`. Ative **Authentication → Providers → Anonymous Sign-Ins**. O aplicativo autentica cada conta localmente, envia cada vídeo à pasta protegida daquela identidade, cria uma URL assinada para a Meta buscar e remove o objeto após confirmação. A limpeza de objetos antigos é tentada após 48 horas enquanto o aplicativo estiver aberto. A chave pública e a URL ficam em `.local/posting-storage.json`; as sessões de Storage e tokens Meta são protegidos pelo Windows.

No painel Meta, abra **Configuração da API com login do Instagram**. Registre a URL de retorno do seu projeto Supabase como URI de redirecionamento do login Instagram. Em **Supabase → Edge Functions → Secrets**, configure `INSTAGRAM_APP_ID` e `INSTAGRAM_APP_SECRET` com as credenciais exibidas pelo produto Instagram. O login solicita `instagram_business_basic`, `instagram_business_content_publish` e `instagram_business_manage_insights`. A permissão de Insights é opcional para publicar. O serviço consome cada autorização uma única vez e o Windows protege o token do perfil. Para testar durante o desenvolvimento, adicione o perfil como testador e aceite o convite no Instagram. Para disponibilizar o login a outros perfis profissionais, conclua a análise das permissões e a publicação do app na Meta.

Em **Dashboard → Atualizar métricas**, o aplicativo consulta visualizações e alcance dos até 20 Reels mais recentes publicados pela fila local, usando a conexão e o proxy de cada conta. Os resultados ficam no SQLite local. Cada atualização bem sucedida também salva uma leitura histórica; os gráficos e cards de visualizações e alcance mostram o crescimento observado entre pelo menos duas leituras reais no período escolhido. Antes disso, exibem ausência de dados. Contas vinculadas antes de solicitar `instagram_business_manage_insights` precisam usar **Contas → Reconectar Instagram** para conceder a nova permissão; a autorização anterior não muda sozinha. A soma de alcance por Reel não representa pessoas únicas entre vários vídeos. A atualização é manual e depende dos dados que a Meta disponibilizar para cada Reel.

Para as métricas do TikTok, crie um aplicativo no [TikTok for Developers](https://developers.tiktok.com/) com **Login Kit para Desktop** e **Display API**, solicitando `user.info.basic`, `user.info.profile` e `video.list`. Cadastre `http://127.0.0.1:3455/callback/` como URI de retorno. Em **Dashboard → Configurar TikTok**, informe a Client Key e o Client Secret; o segredo fica criptografado localmente pelo Windows e não é enviado à interface após salvar. Em **Contas**, escolha **Conectar métricas TikTok** para cada perfil e confirme a identidade autorizada. **Atualizar métricas** consulta os 20 vídeos públicos mais recentes de cada conta conectada, incluindo visualizações, curtidas, comentários e compartilhamentos. As leituras ficam no SQLite local e a variação exige pelo menos duas consultas no período. O login de métricas usa uma sessão separada da automação. A API de vídeos não fornece alcance único nem tempo de exibição. O TikTok precisa aprovar o aplicativo e seus escopos; sem essa aprovação, a conexão real não pode ser testada. Insights do X continuam indisponíveis.

Adicione vídeos MP4 ou MOV próprios/autorizados. O app verifica duração, codec, taxa de quadros, áudio, bitrate, largura, tamanho e legenda com FFprobe antes do envio. Para corrigir incompatibilidades, use **Mídia** e adicione o arquivo preparado. A preparação exporta AAC 48 kHz/128 kb/s, limita o vídeo a 25 Mb/s e a largura a 1920 px. Cada conta tem sua própria fila, intervalo aleatório mínimo/máximo, dias, janela diária, fuso e limite diário opcional. A prévia de horários é estimada; o horário sorteado após uma publicação fica salvo. A janela começa no horário inicial e termina antes do horário final. Ao esgotar a fila, o programa para. Fechar o app pausa a programação e requer **Continuar** ao reabrir; mantenha o computador ligado e sem suspensão.

No cartão de cada conta Instagram, escolha uma pasta e uma capa opcional. Depois de salvar a capa, a miniatura aparece no cartão e pode ser ampliada com um clique. Ao escolher ou trocar a pasta, o app enfileira automaticamente os MP4/MOV presentes naquele momento em ordem natural pelo nome e ignora os já adicionados; selecione a pasta novamente para incluir arquivos novos. Na postagem, a capa da conta é inserida por 0,2 segundo, o vídeo recebe as variações e a limpeza de metadados da função Mídia e o MP4 temporário é validado e enviado. Os originais permanecem na pasta. A capa também vale para vídeos atribuídos à conta pela fila única.

No mesmo cartão, **Ordem dos vídeos** define como a fila da conta escolhe o próximo Reel. **Sequência** segue a ordem exibida e é o padrão das contas existentes; **Aleatório** sorteia um dos vídeos pendentes a cada postagem. A fila única mantém a própria agenda.

O aplicativo envia no máximo um Reel por conta e duas contas simultaneamente. Chamadas locais à Meta e uploads ao Supabase usam a conexão e o proxy configurados para a conta. A Meta baixa o vídeo diretamente do Supabase. Se uma falha ocorrer antes da publicação, há no máximo três tentativas com espera crescente. Se a resposta da publicação for incerta, a conta pausa e exige conferência do perfil; o vídeo não é reenviado automaticamente. Após conferir, marque o resultado no cartão. Se não tiver sido publicado, adicione o vídeo de novo explicitamente. A publicação no X não faz parte desta etapa.

Se um vídeo mostrar **Precisa de atenção**, corrija a causa indicada (proxy, autorização ou arquivo) e clique em **Tentar novamente**. O vídeo volta à fila, mas a conta permanece pausada até você clicar em **Continuar**. A nova tentativa recebe seu próprio limite de três falhas anteriores à publicação. Vídeos com resultado incerto exigem conferência e não oferecem essa ação.

Validação: `npm test`, `npm run test:desktop`, `node tests/meta-exchange-live.cjs` (código OAuth inválido, sem publicação), o teste Electron de Storage em `tests/posting-storage-live.cjs` (com `STUDIO_SUPABASE_URL` e `STUDIO_SUPABASE_KEY` no ambiente) e `tests/posting-proxy-live.cjs` para conexão direta, proxy HTTP autenticado e proxy indisponível (com `STUDIO_PROXY_ID` opcional). Esses testes não publicam conteúdo. Um teste real requer uma conta profissional autorizada, a URL de retorno cadastrada no ClubXone e um vídeo com autorização específica para o envio.

Ao atingir o limite por hora, use **Reiniciar ciclo** no painel ou no menu da janela da conta. O aplicativo pergunta “Você atingiu o limite que definiu. Deseja continuar?”. **Sim** inicia uma nova contagem com o mesmo limite, somente para essa conta; **Não** mantém a espera. O histórico, os contadores de comentários confirmados e a proteção contra duplicação permanecem. O limite total da campanha continua valendo. A autorização do novo ciclo vale enquanto o aplicativo estiver aberto.

Aplicativo local para Windows. Abra `iniciar.cmd` para iniciar.

- **Contas:** adicione, edite e exclua contas TikTok, Instagram ou X. Cada conta mantém janela, sessão e proxy próprios. Excluir uma conta fecha sua janela e apaga os dados de login salvos localmente para ela. TikTok e X possuem páginas de execução separadas; Instagram permanece disponível para login e navegação.
- **Proxies:** cole `IP:porta:usuário:senha` ou preencha os campos. Ao salvar, o aplicativo testa a conexão HTTPS e só cadastra a proxy quando recebe um IP de saída válido. Depois, você pode testar novamente, editar ou excluir. Antes de excluir uma proxy em uso, troque a conexão das contas vinculadas.
- **Navegador pela proxy:** em **Proxies**, informe um endereço HTTPS (Gmail é o padrão) e abra um navegador com sessão própria da proxy. Para compartilhar a sessão com uma conta Instagram vinculada, use **Abrir no navegador de [conta]**. Feche o navegador antes de editar ou excluir a proxy. Isso usa a mesma sessão da janela da conta; a publicação de Reels continua pela autorização da Meta.
- **Localização:** após **Testar proxy**, o aplicativo mostra o IP de saída e uma estimativa de cidade, região, país e rede. Fonte: [ipapi.is](https://ipapi.is/). A estimativa pode diferir da localização exibida pelo TikTok.
- **Campanha:** escolha uma ou várias hashtags, uma busca por palavra/frase ou o feed Para você, além das frases, contas, tempo no vídeo e limites. Com várias hashtags, defina o intervalo mínimo e máximo de vídeos; o app sorteia o momento da troca e percorre as hashtags em sequência. Clique em **Salvar configuração**.
- **Página principal — Para você:** usa os vídeos recomendados em `tiktok.com/foryou`, não os vídeos do perfil. Publica os comentários salvos e pode curtir ou favoritar com porcentagens independentes. LIVE e publicidade são ignoradas automaticamente, sem nenhuma interação. Esse modo aceita uma conta por campanha.
- **Verificar acesso:** abre um vídeo da busca na primeira conta selecionada e confere a identidade e o editor, sem publicar, curtir ou favoritar. Mostra se o @ veio da navegação da sessão ou do cadastro.
- **Iniciar campanha:** após a confirmação, o app mostra o navegador de cada conta selecionada, abre os vídeos, aguarda o tempo configurado e tenta publicar as frases. As janelas podem ser minimizadas depois que abrirem. **Parar** interrompe a execução. O histórico mostra as tentativas e permite abrir o vídeo para conferir.
- **Tema:** use o botão no canto superior direito. A escolha fica salva neste computador.
- **Pausar / Continuar:** suspende a campanha e retoma a mesma fila, preservando contadores e ordem das frases enquanto o aplicativo estiver aberto. Se um comentário estiver sendo enviado, conclui a confirmação antes de pausar. **Parar** encerra a execução.
- **Recuperação automática:** preserva fila, hashtag ativa, contador de troca, frase, sorteio e vídeo pendente enquanto o aplicativo estiver aberto. Uma falha anterior ao envio não marca o vídeo como concluído. Depois de acionar o envio, resultados incertos ficam registrados e não recebem outro clique automático.
- **Conta em atenção:** tenta abrir o editor por 15 segundos, abre novamente e aguarda mais 15 segundos. Três falhas consecutivas colocam somente essa conta em atenção. **Continuar**, no cartão da conta, retoma o vídeo pendente. Comentários explicitamente desativados são pulados.
- **Identidade:** o autor do vídeo não é usado como identidade da sessão. Na falta de um controle inequívoco na navegação global, usa o @ cadastrado. Mantenha esse cadastro correto. Um identificador numérico só equivale a outro @ com evidência no endereço canônico do mesmo vídeo.
- **Segundo plano:** depois de iniciadas, as janelas podem ser minimizadas. Use **Contas → Focar janela** para acompanhar ou fazer login. Fechar o aplicativo encerra a execução. O computador precisa permanecer ligado e sem suspensão.
- **Várias contas:** as contas selecionadas trabalham ao mesmo tempo, cada uma com sua própria sessão, proxy e janela. O limite da campanha continua sendo compartilhado; uma conta em atenção não pausa as demais.
- **Verificação humana:** se o TikTok mostrar um quebra-cabeça ou CAPTCHA, a janela da conta vem para frente e somente essa conta aguarda. Resolva o desafio manualmente; o app identifica o desbloqueio e continua sozinho, enquanto as outras contas permanecem ativas. O app não tenta contornar a verificação.
- **Preparar mídia:** selecione vídeos em lote, uma capa opcional e a pasta de saída. A capa é inserida no início do vídeo. Cada vídeo recebe variações aleatórias imperceptíveis — recorte de borda, micro-ajustes de cor, brilho, saturação e velocidade, recodificação com parâmetros únicos — para que a plataforma interprete o arquivo como um vídeo novo. Todos os metadados pessoais, tags de encoder e marcas de origem são removidos. Os originais não são alterados. Requer FFmpeg e FFprobe disponíveis no computador.
- **Baixar por links:** cole até 200 links ou um bloco de links em Markdown. O app extrai apenas páginas diretas de vídeo, normaliza Reels do Instagram, ignora perfis, Direct, Explorar, rodapés e páginas institucionais, e mostra somente uma contagem compacta. Os downloads públicos chegam em até 1080p e entram automaticamente na lista de preparação. Use apenas conteúdos próprios ou autorizados.

Os cadastros ficam em `.local/` e as credenciais do proxy são protegidas pelo sistema operacional. O histórico diferencia vídeo próprio, sorteio, vídeo já processado, comentários desativados e falha técnica. Fechar ou parar a campanha encerra a fila em memória; tentativas de envio continuam salvas para evitar duplicação.

Testes: `npm test` executa regressões locais; `npm run test:dom` executa os seletores reais em páginas fictícias renderizadas pelo Electron, sem contas nem acesso ao TikTok; `npm run test:desktop` inclui essa suíte e a interface. Uma suíte local aprovada não substitui a verificação da página atual do TikTok.

## Aquecimento X — versão local

Use **Aquecimento X** no menu lateral. **Campanha TikTok** mantém sua própria configuração e execução; as duas podem funcionar ao mesmo tempo. O menu **Histórico** reúne ações do TikTok e do X em ordem de data, identificadas pela plataforma. Contas e proxies são compartilhados, mas cada página seleciona somente contas da sua plataforma.

1. Cadastre contas do X em **Contas**, abra suas janelas e faça login manualmente.
   Ao reabrir, o aplicativo carrega a página inicial do X com a sessão salva. O menu **Navegar → Entrar no X** permite abrir o login explicitamente. A verificação aguarda o carregamento da navegação da conta antes de avaliar a identidade.
2. Escolha **Só curtir**, **Só responder** ou **Ambos**. Hashtags permitem a ordenação **Mais recentes** ou **Principais**. Palavras e frases pesquisam posts com fotos, GIFs ou vídeos na aba **Top (Principais)**; nesse caso, **Ambos** responde antes de curtir. Cada rodada usa a quantidade sorteada no intervalo mínimo/máximo de posts. O filtro de recência inicia em 50 minutos e ignora posts sem data reconhecida, inclusive resultados Top mais antigos.
3. Insira respostas, uma por linha. Cada conta embaralha sua lista e inicia outro ciclo ao esgotá-la, evitando repetir imediatamente a última frase quando houver alternativas. **Testar variação** só mostra uma prévia.
4. Preencha os intervalos mínimo/máximo, o limite de ações por hora por conta e o limite total compartilhado. Esses campos não possuem valores automáticos. Em **Ambos**, uma curtida e uma resposta consomem duas ações. Resultados incertos também consomem limite; posts já curtidos não.
5. Salve e use **Verificar acesso** para consultar a busca sem publicar ou curtir. **Iniciar aquecimento** executa as ações configuradas nas contas selecionadas.

**Pausar / Continuar** preserva a fila em memória; também há controle individual por conta. O limite horário usa uma janela móvel de 60 minutos e aguarda automaticamente. O total da sessão encerra a execução. Sem novos posts elegíveis, a pesquisa espera 60 segundos. **Parar** impede novas ações e aguarda a confirmação da ação atual; fechar o aplicativo não retoma automaticamente a execução ao reabrir.

Login explícito, desafios, restrições, troca de identidade e rascunhos não reconhecidos exigem atenção manual à conta afetada e **Continuar conta**. Falhas técnicas de leitura e editor são tratadas por recuperação automática. As demais contas permanecem independentes. Configurações, conexão e exclusão de contas em execução ficam protegidas. O aplicativo não resolve desafios nem contorna bloqueios. Ele precisa permanecer aberto, com o computador ligado e sem suspensão.

O histórico diferencia confirmação, resultado incerto, falha anterior ao envio e curtida já existente. Uma intenção de envio é salva antes do clique. Após reiniciar, registros pendentes são considerados incertos; não há repetição automática de ações confirmadas ou incertas para o mesmo post e conta. As confirmações dependem dos elementos visíveis do X; mudanças no site podem exigir atualização dos seletores.

As [regras de automação do X](https://help.x.com/en/rules-and-policies/x-automation) proíbem curtidas automáticas e respostas automáticas baseadas apenas em buscas. Limites e pausas não garantem evitar restrições.

**Validação real em 03/11/2026:** consulta de busca e identificação de sessão funcionaram em uma conta; uma segunda conta não teve a identidade confirmada. Nenhuma curtida ou resposta real foi enviada. Envio e confirmação foram exercitados em páginas fictícias; a publicação real permanece sem validação de ponta a ponta.

`npm run test:x:read-only` consulta a hashtag `tecnologia` nas contas X cadastradas, usando suas sessões e proxies, sem interações. Execute com o aplicativo fechado. O resultado sem credenciais fica em `.smoke/x-live-readonly-result.json`. Esse diagnóstico não inicia campanhas nem altera a configuração salva.

A origem da prospecção no X pode ser **Hashtags**, **Palavras ou frases** (uma busca por linha) ou **Página principal — Para você**. Configurações antigas continuam usando hashtags. No feed, cada conta usa suas recomendações e o app confere a seleção da aba Para você antes de ler os posts. Recentes/principais se aplica somente às buscas. As três origens compartilham os mesmos filtros, limites e controles por conta.

No X, **Trocar após no mínimo / no máximo** define o intervalo de posts examinados antes de avançar para a próxima hashtag, palavra ou frase. Cada conta sorteia sua quantidade a cada rodada. Resultados esgotados antecipam a troca. O controle fica oculto em Para você. Configurações antigas preservam o limite anterior de 20 posts até serem alteradas e salvas.

**Recuperação automática do X:** falhas de leitura têm três tentativas; falhas anteriores ao envio reabrem o mesmo post uma vez e, persistindo, pulam essa ação pelo restante da sessão. Uma falha de confirmação registra resultado incerto, preserva os limites e avança ao próximo post sem repetir o envio nem executar as ações restantes naquele post. Após três falhas consecutivas, a conta aguarda 60 segundos e tenta continuar; pausar e parar funcionam durante a espera. A interface mostra o motivo e os contadores de recuperações e resultados incertos. O histórico preserva o erro da tentativa. Rascunhos criados pelo aplicativo só são limpos automaticamente quando o post e o texto permanecem exatamente iguais aos registrados em memória.
